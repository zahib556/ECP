# Записка: анализ безопасности проекта (SAST/SCA)

Проект: «Средство выработки и проверки ЭЦП» (СТБ 34.101.45-2013), Python (PySide6) + Rust-ядро (`pyo3`). Практическая работа ПЗ-7.

## 1. Подход

Собственный анализатор не разрабатывался: проект проверен готовыми open-source инструментами, которые встроены в репозиторий
(конфигурации, скрипт локального запуска, workflow GitHub Actions). Это соответствует общей схеме из задания:
сбор файлов -> разбор -> правила / сверка с базой -> отчёт -> код возврата.

| Задача | Инструмент | Что проверяет | Метод | Запуск |
|---|---|---|---|---|
| SAST, Python | [Bandit](https://github.com/PyCQA/bandit) | исходники `python/`, `tools/`, `main.py` | AST (плагины-проверки на узлах дерева разбора) | локально и в CI |
| SAST, Python | [Semgrep](https://github.com/semgrep/semgrep) (наборы `p/python`, `p/security-audit`, `p/secrets`) | то же, плюс поиск секретов | сопоставление с образцами по синтаксическому дереву | CI (на Windows не работает) |
| SCA, Python | [pip-audit](https://github.com/pypa/pip-audit) | `PySide6`, `cryptography` и их транзитивные зависимости | сверка версий с базой уязвимостей PyPI (PyPA Advisory Database) | локально и в CI |
| SCA, Rust | [cargo-audit](https://github.com/rustsec/rustsec) | крейты из `Cargo.toml` / `Cargo.lock` | сверка с RustSec Advisory Database | CI |

Версии инструментов (заполнить после установки, команда `pip freeze | findstr /i "bandit pip-audit"`):

    bandit==_____   pip-audit==_____   semgrep==_____   cargo-audit==_____   Python 3.__.__

## 2. Анализ проекта: потенциально опасные места (этап 1)

Составлено ручным обзором кода до запуска инструментов.

| Область | Где | Что там |
|---|---|---|
| Запуск процессов | `update/installer.py` (`subprocess.run`, `subprocess.Popen`), `update/updater.py` (`subprocess.Popen`), `tools/build_update.py` | аргументы передаются списком, без `shell=True`; команда запуска формируется внутри программы |
| Распаковка архивов | `update/staging.py` (`zipfile`) | защита от Zip Slip и «бомб» реализована вручную; проверяется тестами ПЗ-6, статическими правилами Bandit не покрывается |
| Аутентификация | `auth/passwords.py`, `auth/tokens.py`, `auth/service.py` | PBKDF2-HMAC-SHA256, токены HS256, сравнение через `hmac.compare_digest`, ключ подписи в файле с правами `0o600` |
| База данных | `auth/store.py` (`sqlite3`) | запросы параметризованные (`?`), построения SQL конкатенацией нет |
| Обработка ошибок | `auth/device.py` (`except Exception: pass`), `gui/*` (`except Exception` с показом сообщения), `assert` в `auth/service.py`, `cades.py` | `assert` может быть вырезан при запуске с `-O` |
| Секреты | `update/pubkey.py`, `dev_keys/` | в коде только открытый ключ проверки обновлений; закрытые ключи в `.gitignore` |
| Криптография | `src/lib.rs`, `cryptoif.py` | собственных схем нет, используются крейты `belt-*`, `bign256` |

Зависимости: Python — `PySide6`, `cryptography` (в `pyproject.toml` без версий, поэтому берутся версии из окружения);
Rust — `pyo3 0.23`, `belt-hash 0.1`, `belt-block 0.1`, `num-bigint 0.4`, `bign256 0.13`, `rand_core 0.6`.

## 4. Уровень анализа и ограничения

- **Bandit** работает на уровне AST: точно указывает файл, строку и столбец, не срабатывает на комментарии и строки,
  у каждой находки есть уровень критичности (severity), уверенность (confidence) и CWE. Потока данных он не отслеживает.
- **Semgrep** сопоставляет образцы по синтаксическому дереву; в бесплатной версии без межпроцедурного анализа.
  Наборы `p/security-audit` и `p/secrets` ловят то, чего нет в Bandit (секреты, общие небезопасные образцы).
  Для Rust покрытие правилами слабее, чем для Python: код `src/lib.rs` проверяется в основном через SCA (`cargo-audit`).
- **SCA** видит только то, что есть в базах: неизвестные уязвимости не найдёт; транзитивные зависимости Python берутся
  из `pip freeze` чистого окружения, транзитивные зависимости Rust — из `Cargo.lock` (его нужно хранить в репозитории).
- Ни один из инструментов не проверяет логику: защита от Zip Slip, корректность проверки подписи и политики
  паролей закрыты тестами ПЗ-6, а не анализаторами.
- Ложные срабатывания: часть правил Bandit (`B404`, `B603`, `B101`) носит информационный характер для обычной настольной программы.

## 5. Подавление ложных срабатываний

| Где | Как | Пример |
|---|---|---|
| Bandit, одна строка | комментарий `# nosec` с номером правила и причиной | `subprocess.run(cmd)  # nosec B603 - аргументы формирует программа, без shell` |
| Bandit, каталоги | `exclude_dirs` в `bandit.yaml` | тесты и фаззинг исключены |
| Bandit, порог | `-ll` (Medium и выше), `-lll` (только High); `-i` / `-ii` — по уверенности | в CI сборка падает только на High |
| Semgrep, одна строка | `# nosemgrep: <id правила>` | |
| Semgrep, каталоги | `.semgrepignore` | |
| pip-audit | `--ignore-vuln <ID>` с записью причины в отчёте | |
| cargo-audit | `cargo audit --ignore RUSTSEC-ГГГГ-НННН` или `audit.toml` | |

Подавление допустимо только с письменной причиной рядом с кодом или в таблице разбора (раздел 3).

## 6. Как воспроизвести

    pip install -r requirements-security.txt
    .\tools\run_security.ps1                 # Bandit + pip-audit, отчёты в security-reports\
    # Semgrep и cargo-audit: GitHub -> Actions -> security -> Run workflow, артефакты sast-reports и sca-reports
