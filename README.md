# ecp: средство выработки и проверки ЭЦП (СТБ 34.101.45-2013)

Python + PySide6 (GUI), Rust (bign256, belt-hash, belt-block) через PyO3/Maturin.

## Сборка и запуск (Windows 11, PowerShell)

    python -m venv .venv
    .\.venv\Scripts\Activate.ps1
    pip install maturin pytest PySide6 cryptography
    maturin develop        # только после изменения Rust-кода (src/lib.rs, Cargo.toml)
    pytest -v
    python -m ecp.gui

Командная строка: `python -m ecp --version`, `python -m ecp --check`.

## Выпуск релиза (в самом конце, когда код заморожен)

    python tools/build_release.py keygen     # один раз: ключи разработчика (dev_keys/ не распространять)
    python tools/build_release.py sign       # подписывает контрольные хэши файлов
    python tools/build_release.py check

Если в `python/ecp/` остался файл `MANIFEST.json` старого формата, удалите его.
После `sign` любое изменение файлов программы блокирует работу самотестированием.

## Файлы пользователя

Конфигурация, журнал и состояние: `%APPDATA%\ecp\` (`config.ini`, `logs\security.log`, `state.json`).
Локальная служба штампов времени (создаётся при первом обращении): `tsa.key`, `tsa.cer` в той же папке.

## Состав

- `src/lib.rs` - Rust-ядро: belt-hash, hmac-hbelt, brng-ctr, ключи, k (п. 6.3.3), ЭЦП (п. 7.1.3-7.1.4)
- `python/ecp/service.py` - слой приложения, самотестирование
- `python/ecp/asn1.py`, `x509.py`, `cades.py` - ASN.1 DER, сертификат, расширенная ЭЦП CAdES-B-B / B-T
- `python/ecp/tsp.py` - штамп времени (СТБ 34.101.82): запрос, локальная служба, проверка ответа
- `python/ecp/config.py`, `audit.py`, `logview.py`, `context.py` - конфигурация, журнал событий, анализ журнала
- `python/ecp/manifest.py` - целостность и подлинность ПО (подписанный манифест)
- `python/ecp/auth/` - аутентификация пользователей (см. раздел ниже)
- `python/ecp/update/` - безопасное обновление ПО (см. раздел «Обновление ПО»)
- `python/ecp/gui/` - интерфейс (`login_dialog.py` - экран входа и регистрации)

## Аутентификация пользователей

Приложение при запуске (`python -m ecp.gui`) показывает окно входа; без входа главное окно не открывается,
а все операции с файлами, ключами, штампами времени и конфигурацией отклоняются (`Ошибка: требуется вход в систему`).
Командная строка (`--version`, `--check`) и тесты работают без входа.

Вместо REST-маршрутов (разрешено заданием) используются модули пакета `ecp.auth`:

| Маршрут | Вызов | Назначение |
| --- | --- | --- |
| POST /register | `AuthService.register(login, password, device_id)` | регистрация, возвращает одноразовый код сброса |
| POST /login | `AuthService.login(login, password, device_id)` | вход, выдаёт JWT-токен |
| POST /logout | `AuthService.logout(token)` | завершение сессии (токен становится недействительным) |
| GET /me | `AuthService.me(token, device_id)` | проверка текущей сессии |

**Пароли.** PBKDF2-HMAC-SHA256, 310 000 итераций (не менее 200 000), уникальная случайная соль 16 байт на пользователя.
В БД хранятся `login` (в нижнем регистре), `password_hash` (`pbkdf2_sha256$итерации$хэш`), `salt`, `device_id`,
`created_at`, `last_seen`. Пароль в открытом виде нигде не сохраняется и в журнал не пишется.

**Токен.** JWT HS256 (подпись ключом из файла `auth.key` в папке пользователя), срок жизни 30 минут, в claims -
`sub`, `login`, `did` (device_id), `iat`, `exp`, `jti`. Токен проверяется при каждой защищённой операции и привязан
к `device_id`. Клиент хранит его только в оперативной памяти; при истечении происходит возврат на экран входа.

**Файлы.** `users.db` (таблицы `users`, `sessions`, а также `login_attempts`, `reset_codes`) и `auth.key` лежат
в `%APPDATA%\ecp\`. Файл `auth.key` не распространять.

**device_id.** `SHA-256("hostname|platform|mac|machine_id")`, где `platform` = `platform.system() platform.release()`,
`mac` = `uuid.getnode()` (12 hex-цифр), `machine_id` = `MachineGuid` из реестра (Windows) или `/etc/machine-id` (Linux).
При первом входе устройство запоминается; с другого устройства вход отклоняется
(`Ошибка: вход с незнакомого устройства`), если пароль верен.

**Дополнительные задания.**
- Ограничение попыток: 5 неудачных входов подряд блокируют логин на 5 минут (в том числе несуществующий логин).
- Сброс привязки устройства: кнопка «Сбросить привязку устройства…» на экране входа; нужны логин, пароль и
  одноразовый код, выданный при регистрации (после сброса выдаётся новый код, прежние сессии закрываются).
- Аудит входов: источник `ecp.auth` в журнале (время, IP, пользователь, короткий префикс `device_id`, результат).
  После входа поле «учётная запись» в журнале содержит логин пользователя.

Порядок запуска: `python -m ecp.gui` -> вкладка «Регистрация» (сохранить код сброса) -> вкладка «Вход».

## Обновление ПО (практическая работа ПЗ-4, вариант Б - монолитное приложение)

Только **offline**: сервера нет, обновление ставится из локального подписанного пакета. Вкладка «Обновление ПО»
(доступна после входа) -> выбрать `manifest.json` -> «Проверить» -> «Установить и перезапустить».

**Не путать с самопроверкой целостности.** `MANIFEST.json` (заглавными) в `python/ecp/` - хэши файлов программы,
подписанные ЭЦП СТБ (belt-hash + bign), проверяются при каждом запуске. `manifest.json` (строчными) - манифест
обновления, подписан Ed25519. Это разные файлы; служебные `manifest.json` и `manifest.sig` из пакета никогда не
распаковываются в каталог программы (на Windows имена различались бы только регистром).

**Содержимое релиза** (папка `release/`):

    ecp-1.3.0-windows-x64.zip   файлы программы + sbom.json
    manifest.json               подписанный манифест
    manifest.sig                подпись (base64), копия поля "signature"

Хэш ZIP не может лежать внутри самого ZIP, поэтому манифест находится рядом с пакетом.

**Формат manifest.json:** `version`, `min_supported`, `release_date` (UTC, `2026-10-23T10:00:00Z`), `os`
(`windows`/`linux`/`macos`), `arch` (`x64`/`arm64`/`x86`), `package_url` (используется только имя файла),
`package_size`, `package_sha256`, `sbom` {`format` = `CycloneDX-1.5`, `url`, `sha256`}, `critical`, `signature`.
Подписывается каноническая форма без поля `signature` (ключи по алфавиту, без пробелов, UTF-8). Повторяющиеся
поля JSON отклоняются.

**Порядок проверки (любой сбой - отказ, запись в `update_audit` и журнал, файлы программы не тронуты):**
1. подпись Ed25519 (открытый ключ вшит: `python/ecp/update/pubkey.py`);
2. совместимость: `min_supported` <= текущая версия (иначе блокировка, нужна установка «с нуля»), версия новее
   текущей (понижение запрещено), ОС и архитектура совпадают;
3. размер и SHA-256 пакета;
4. распаковка в `ecp.staging/` с защитой от Zip Slip, символьных ссылок, повторов имён и «ZIP-бомб»;
5. SBOM: SHA-256 совпадает с манифестом, формат CycloneDX 1.5, версия приложения в SBOM = версии обновления,
   присутствуют ключевые зависимости (`PySide6`, `cryptography`), нет дублей, `purl` соответствует имени и версии;
   при расхождении статус `sbom_mismatch`;
6. приложение закрывается, отдельный процесс (`installer.py`, только стандартная библиотека) переименовывает
   `ecp -> ecp.backup`, `ecp.staging -> ecp`;
7. проверка запуска новой версии (`--check` должен вернуть 0); при ошибке на любом шаге замены - откат из `ecp.backup`,
   затем запускается восстановленная версия. Итог процесс пишет в `update_result.json`, приложение вносит его в
   `update_audit` при следующем запуске.

**Журнал обновлений:** таблица `update_audit` в `users.db` (поля по заданию, статусы `verified`, `installed`, `failed`,
`rolled_back`, `sbom_mismatch`) и журнал событий (источник `ecp.update`). Видны в нижней таблице вкладки.

**Выпуск обновления (разработчик):**

    pip install pyinstaller
    python tools/build_update.py keygen                  # один раз; ключ dev_keys/update_signing.key не распространять
    # пересобрать приложение: открытый ключ вшивается в python/ecp/update/pubkey.py
    python tools/build_update.py exe                     # dist/ecp (--onedir) + ecp-updater.exe
    python tools/build_update.py package --version 1.3.0 --min-supported 0.5.0 --source dist/ecp

**Сборка `.exe` одной командой (Windows, из активного venv с установленным `maturin develop`):**

    pip install pyinstaller
    python tools/build_update.py keygen            # один раз
    python tools/build_update.py release --version 1.3.0 --min-supported 0.5.0 [--signtool]

Команда по шагам: записывает версию в `python/ecp/version.py` (версия внутри программы должна совпадать с версией
пакета) -> PyInstaller `--onedir --windowed` (`dist/ecp/ecp.exe`, `_internal/`) и `ecp-updater.exe` рядом -> по `--signtool`
подпись обоих `.exe` и `signtool verify /pa` -> пробный запуск `ecp.exe --check` (при ошибке пакет не создаётся) ->
ZIP + `sbom.json` -> `manifest.json` и `manifest.sig` в `release/`. Если открытый ключ не вшит, команда остановится.

Без `--source` пакет собирается из `python/ecp` (режим исходников). SBOM строится из установленных пакетов
(CycloneDX 1.5; `cyclonedx-py` не требуется). Подпись `.exe` через SignTool (по желанию) делается до упаковки:
SHA-256 считается от финального ZIP. После изменения файлов программы заново выполните `build_release.py sign`.

**Ограничения:** online-режим и серверные маршруты `/updates/*` (вариант А) не реализованы; интерфейс
`IUpdateSource` для них предусмотрен. Сборка `.exe` и установка на запущенное приложение Windows в песочнице
разработки не проверялись.
